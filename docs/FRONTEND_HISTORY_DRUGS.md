# История болезней: выбор препаратов = раздел «Лекарства»

## Баг (скриншоты)

| Где | «Креон» |
|-----|---------|
| **Лекарства** → поиск | Находит (Креон 10000, 25000, …) |
| **История болезней** → «Выберите препараты» | Пусто |

**Причина:** модалка истории берёт **неполный** список (часто `page=1` без `q`, или `drugs` из карточки болезни).  
Каталог один. Источник для пикера должен быть **тот же**, что у раздела «Лекарства».

RuTronix здесь **не участвует**. RuTronix — AI / OCR / помощник. Справочник лекарств — **БД каталога** (`GET /api/catalog/drugs/`).

---

## Обязательное правило для FE

Модалка **«Выберите препараты»** = тот же API, что экран **«Лекарства»**.

### Вариант A (рекомендуется) — как поиск в «Лекарства»

При каждом вводе (debounce ~300 ms):

```http
GET /api/catalog/drugs/?q=Креон&page=1&page_size=50
```

Ответ:

```json
{
  "count": 4,
  "page": 1,
  "page_size": 50,
  "results": [
    { "id": 123, "name": "Креон 10000", "description_preview": "…", "dosage": "…" }
  ]
}
```

UI показывает `results`. Выбранные `id` → в запись истории как `drug_ids`.

### Вариант B — полный список + локальный фильтр

Если модалка открывается **без** серверного `q` и фильтрует локально (как болезни):

```http
GET /api/catalog/drugs/?picker=1
```

Ответ — **JSON array** (не `{results:…}`):

```json
[
  { "id": 123, "name": "Креон 10000", "dosage": "…" },
  { "id": 124, "name": "Креон 25000", "dosage": "…" }
]
```

Потом локальный `contains` по `name`. Это **весь** активный каталог, тот же, что «Лекарства».

---

## Сохранить в историю

`POST` / `PATCH` записи болезни — поле `drug_ids: [123, 124]`  
(id из каталога выше). Любой препарат из справочника можно привязать, даже если он не связан с выбранной болезнью в М2М.

---

## Запрещено (из‑за этого «Креон» пропадал)

| Нельзя | Почему |
|--------|--------|
| Только `GET /api/catalog/drugs/` без `q` и без `picker=1`, взять `results` page 1 | Макс. ~50 шт., «Креон» может не попасть |
| Локальный фильтр по этим 50 | Пустой список при валидном препарате |
| `GET /api/catalog/diseases/{id}/` → поле `drugs` / `related_drugs` | Лишь связанные с болезнью, урезанный список |
| `?disease_id=` в пикере «добавить любой препарат» | Снова не полный каталог |
| Ждать список от RuTronix / Gemini | Каталог не из LLM |

---

## Чеклист перед релизом (FE)

- [ ] Модалка истории вызывает `/api/catalog/drugs/` (A или B выше)
- [ ] Ввод «Креон» даёт те же позиции, что раздел «Лекарства»
- [ ] Сохранение шлёт `drug_ids` из ответа каталога
- [ ] Нет отдельного «урезанного» кеша препаратов для истории

## Flutter (кратко)

```dart
// Вариант A — как «Лекарства»
final res = await api.get('/catalog/drugs/', queryParameters: {
  'q': query.trim(),
  'page': 1,
  'page_size': 50,
});
final items = res.data['results'] as List;

// Вариант B — один раз при открытии модалки
final res = await api.get('/catalog/drugs/', queryParameters: {'picker': '1'});
final items = res.data as List; // array
```

## Связанные справочники (та же логика)

| Пикер | Endpoint | Неполный источник |
|-------|----------|-------------------|
| Болезнь | `GET /api/catalog/diseases/` | — |
| Препарат | `GET /api/catalog/drugs/?q=` или `?picker=1` | `diseases/{id}.drugs` |
| Город | `GET /api/geo/cities/` | урезанный major-only |

Повторяющийся баг «в одном разделе есть, в пикере нет» = **другой/урезанный API**. Всегда один канонический список.
