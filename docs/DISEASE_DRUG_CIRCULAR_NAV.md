# MedicAI — Круговая навигация: Заболевания ↔ Лекарства

Документация для мобильного фронтенда (Flutter).

**Base URL (prod):** `http://85.198.101.179:8007/api/`  
**Auth:** для этих endpoint’ов не обязателен (`AllowAny`).

---

## Идея (как хочет клиент)

Навигация должна работать **по кругу без конца**:

1. Открыли **болезнь** → внизу список **лекарств** (кликабельные).
2. Нажали лекарство → открылось **полное описание лекарства** + внизу список **болезней**.
3. Нажали болезнь → снова описание болезни + список лекарств.
4. И так далее бесконечно.

То же самое, если начать из раздела **«Лекарства»**.

```
Болезнь ──tap──► Лекарство ──tap──► Болезнь ──tap──► Лекарство ──► …
```

---

## Важно для Flutter

| Неправильно | Правильно |
|-------------|-----------|
| Показать только вложенный объект из списка (короткий preview) | При тапе вызвать **detail** по `id` |
| Показать только `description_preview` | На экране detail брать **`description`** (+ `instructions`) |
| Не рисовать блок болезней у лекарства | Рисовать `diseases` / `related_diseases` внизу |

**Правило (рекомендуется):**  
- Тап по лекарству → `GET /api/catalog/drugs/{id}/`  
- Тап по болезни → `GET /api/catalog/diseases/{id}/`

**Важно (исправление «нет бесконечности»):**  
Вложенные объекты уже содержат следующий уровень связей, даже если Flutter **не** делает повторный GET:

- В `GET /diseases/{id}/` → каждый элемент `drugs[]` содержит `diseases` / `related_diseases`
- В `GET /drugs/{id}/` → каждый элемент `diseases[]` содержит `drugs` / `related_drugs`

Так можно ходить по кругу, используя данные из текущего response.

Alias-поля (одинаковое содержимое):

- `related_drugs` ≡ `drugs`
- `related_diseases` ≡ `diseases`

Можно использовать любое имя поля.

## 1. Список заболеваний

`GET /api/catalog/diseases/?q=&limit=500`

Краткий объект (без вложенных лекарств). Для карточки/поиска.

---

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | int | ID болезни |
| `name` | string | Название (без английских `[brackets]`) |
| `description` | string | Полное описание |
| `description_preview` | string | Короткий текст для превью |
| `drugs` | array | Список лекарств (до 80), активные |
| `related_drugs` | array | То же, что `drugs` (alias) |

### Элемент `drugs[]`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | int | **Обязателен для перехода** → `GET /catalog/drugs/{id}/` |
| `name` | string | Название |
| `description` | string | Текст из БД |
| `description_preview` | string | Короткий preview |
| `instructions` | string | Инструкция |
| `dosage` | string | Дозировка |
| `image` | string\|null | URL картинки |
| `rating` | number | Рейтинг |
| `in_my_cabinet` | bool | Есть ли в аптечке (если юзер залогинен) |

### UI на экране болезни

1. Заголовок: `name`
2. Текст: `description` (не только preview)
3. Блок **«Лекарства»**: список `drugs` / `related_drugs`
4. Тап по элементу → открыть `GET /api/catalog/drugs/{id}/`

## 3. Список лекарств

`GET /api/catalog/drugs/?q=&limit=500`

Каждый элемент уже может содержать `diseases`, но для полного экрана всё равно лучше открывать detail по `id`.

1. Заголовок: `name`
2. Описание: `description` (+ при наличии `instructions`)
3. Блок **«Связанные заболевания»**: список `diseases` / `related_diseases`
4. Тап по болезни → открыть `GET /api/catalog/diseases/{id}/`

## Псевдокод навигации (Flutter)

```dart
// Экран болезни
onTapDrug(drugId) {
  Navigator.push(DrugDetailPage(id: drugId));
  // внутри DrugDetailPage:
  // api.get('/catalog/drugs/$drugId/')
}

// Экран лекарства
onTapDisease(diseaseId) {
  Navigator.push(DiseaseDetailPage(id: diseaseId));
  // внутри DiseaseDetailPage:
  // api.get('/catalog/diseases/$diseaseId/')
}
```

Не передавайте «готовый короткий объект» как единственный источник экрана — всегда подгружайте detail по `id`, чтобы были и полный текст, и нижний список связей.

---

## Чеклист приёмки

- [ ] Из болезни тап по лекарству открывает **полный** экран лекарства (не только 1–2 строки).
- [ ] Внизу у лекарства есть список болезней, элементы кликабельны.
- [ ] Тап по болезни открывает экран болезни со списком лекарств внизу.
- [ ] Можно ходить по кругу: болезнь → лекарство → болезнь → лекарство…
- [ ] То же работает, если старт из раздела «Лекарства».

---

## Контакты по API

Если в response пустой `diseases` / `drugs` — пришлите `id` препарата/болезни.  
На prod у активных лекарств связанные болезни заполнены (покрытие ~100%).
