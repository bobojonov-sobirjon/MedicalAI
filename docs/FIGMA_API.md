# MedicAI: маршрут пользователя, экраны Figma и API

Документ для фронтенда: **один непрерывный порядок** — как пользователь проходит приложение после установки. В каждом блоке сначала **зачем этот шаг** (назначение по ТЗ и по макету), затем **какие запросы** делать.

---

## Как читать этот файл

| Обозначение | Смысл |
|-------------|--------|
| База URL | Все пути ниже с префиксом **`/api/`** |
| Формат | **JSON**, если не сказано `multipart` |
| Защита | **`Authorization: Bearer <access_token>`** для помеченных «JWT» |
| Опция ТЗ §3.3 | При `REQUIRE_BACKEND_API_KEY` — заголовок **`X-Backend-Key`** |
| Источник правды по полям | **Swagger** `/docs/` и схема `/schema/` |

## 0. Стартовый экран и сплэш (ТЗ §7.2)

**Назначение:** первый запуск — выбор «Войти» / «Зарегистрироваться»; при уже сохранённом refresh — сразу в ЛК. Сам сплэш и навигация без сервера.

**Figma:** экран приветствия (например 391).

**API:** обычно не нужен. Опционально перед показом ЛК можно запросить публичные настройки:

| Метод | Путь | Auth | Зачем |
|-------|------|------|--------|
| **GET** | `/api/content/config/` | нет | Показать срок бесплатного периода, контакт психолога и т.п. без входа |

**Ответ:** `{ "free_trial_months": 3, "psychology_email": "…" }`.

## 1. Регистрация (ТЗ §7.3)

**Назначение:** создать учётную запись, получить JWT и профиль, чтобы дальше ходить в ЛК. По ТЗ — телефон + SMS; **в текущем бэкенде** основной поток — **email + username + пароль** (+ опционально телефон в профиле). Соцсети — отдельный метод (п. 2).

**Figma:** форма регистрации (например 377), чекбокс политики — открыть текст из статической страницы.

### 1.1. Текст политики конфиденциальности

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/content/pages/<slug>/` | нет |

`slug` задаётся в админке (часто `privacy`). **Ответ:** `{ "slug", "title", "body" }` — весь HTML/текст для экрана соглашения.

### 1.2. Регистрация по паролю

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/auth/register/` | нет |

**Тело (JSON):**

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `email` | да | Уникальный email |
| `username` | да | Уникальный логин |
| `password` | да | ≥6 символов, минимум 1 буква и 1 цифра |
| `phone_number` | нет | Уникален, если указан |
| `first_name`, `last_name` | нет | Имя и фамилия для ЛК |

**Ответ 201:** `{ "user": { … }, "tokens": { "access", "refresh" } }` — сохраните токены, переходите в ЛК.

> **Отличие от ТЗ:** отдельного API «отправить SMS-код при регистрации» в проекте нет.

## 2. Вход в приложение (ТЗ §7.4)

**Назначение:** узнать пользователя по логину и паролю (или по соцсети) и выдать новую пару JWT.

**Figma:** экран «Вход» (например 378).

### 2.1. Вход по паролю

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/auth/login/` | нет |

**Тело:**

```json
{ "identifier": "email или username или телефон", "password": "…" }
```

**Ответ 200:** `{ "user", "tokens" }`.

### 2.2. Вход через VK / Google / Apple

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/auth/social/` | нет |

**Google / Apple (через Firebase ID token):** `{ "provider": "google"|"apple", "id_token": "…" }`.  
**VK:** `{ "provider": "vk", "platform": "android"|"ios", "code": "…" }` или `access_token` вместо `code`.

**Ответ:** как у логина.

### 2.3. Продление access без повторного логина

**Назначение:** access короткоживущий; по refresh получить новый access без ввода пароля.

| Метод | Путь | Тело |
|-------|------|------|
| **POST** | `/api/auth/refresh/` | `{ "refresh": "…" }` |

**Ответ:** `{ "access": "…" }`.

## 3. Забыли пароль (ТЗ §7.5)

**Назначение:** восстановить доступ по email с кодом из письма (не по SMS в текущей реализации).

**Figma:** ссылка «Забыли пароль?» с экрана входа.

| Шаг | Метод | Путь | Тело |
|-----|-------|------|------|
| 1 | **POST** | `/api/auth/password/forgot/request/` | `{ "email": "…" }` |
| 2 | **POST** | `/api/auth/password/forgot/verify/` | `{ "email": "…", "code": "123456" }` → в ответе `reset_token` |
| 3 | **POST** | `/api/auth/password/forgot/reset/` | `{ "reset_token": "…", "new_password": "…" }` → снова `user` + `tokens` |

## 4. Главная страница ЛК (ТЗ §7.6)

**Назначение:** после входа — обзор: полезные советы/обновления, индикатор уведомлений, плитки разделов (история, заболевания, лекарства, помощник и т.д.). Данные для «карусели» советов и бейджа событий — с сервера.

**Figma:** главная (например 351).

### 4.1. Лента «Полезное» (советы + обновления приложения)

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/me/notifications/useful/` | JWT |

**Зачем:** блок советов сверху и сообщения «Обновление MedicAi» из админки. Советы по болезням приходят в тот же поток, если пользователь подписан (настройки ниже).

**Ответ:** массив `{ type: "update"|"tip", id, title, body, … }` (у `tip` есть `disease_id`).

### 4.2. Настройки советов (лимит в сутки, подписка на полезное)

**Назначение:** ТЗ §7.12.2 / §8.2.3 — ограничить количество советов и включить вкладку «Полезное».

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/me/tip-settings/` | JWT |
| **PATCH** | `/api/me/tip-settings/` | JWT |

**PATCH тело (частично):** `{ "tips_per_day": 1–20, "useful_subscribed": true/false }`.

### 4.3. Подписка на советы по конкретной болезни

**Назначение:** при добавлении болезни в историю пользователь может «Подписаться на советы» — отдельный учёт по болезни.

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/me/disease-tip-subscribe/<disease_id>/` | JWT |
| **DELETE** | `/api/me/disease-tip-subscribe/<disease_id>/` | JWT |

## 5. Профиль пользователя (ТЗ §7.7)

**Назначение:** хранить и редактировать ФИО, ник, пол, город, дату рождения, рост, вес, хронические болезни, COVID, аватар; пин-код; переключение контекста семьи для остальных разделов.

**Figma:** экран профиля (например 268).

### 5.1. Чтение и обновление профиля

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/auth/me/` | JWT |
| **PATCH** | `/api/auth/me/` | JWT |

**PATCH:** JSON или **multipart** (если меняете `avatar`). Поля включают: `first_name`, `last_name`, `nickname`, `phone_number`, `username`, `gender`, `city`, `date_of_birth`, `height_cm`, `weight_kg`, `chronic_diseases`, `had_covid`, `useful_tips_subscribed`, `pin_code` (запись хэша пина на сервере).

### 5.2. Смена пароля из профиля (не «забыли»)

| Метод | Путь | Тело | Auth |
|-------|------|------|------|
| **POST** | `/api/auth/password/change/` | `{ "old_password", "new_password" }` | JWT |

### 5.3. Несколько учётных записей (семья)

**Назначение:** ТЗ §8.2.3 — привязать другого пользователя (родственника), чтобы в истории и помощнике выбирать «для кого».

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/me/family/` | JWT |
| **POST** | `/api/me/family/` | JWT |
| **DELETE** | `/api/me/family/<member_id>/` | JWT |

**POST тело:** `{ "member_id": <id>, "label": "Мама" }`.

**Назначение:** показать все случаи по дате, перейти в карточку, добавить новую запись. Для семьи — вкладки/фильтр по пользователю на клиенте; в API у записи есть `subject_user`.

**Figma:** список истории (например 356).

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/me/disease-records/` | JWT |

**Ответ:** массив кратких записей: `id`, `date_of_illness`, `title`, `disease`, `subject_user`, даты.

## 7. Добавить / редактировать запись о заболевании (ТЗ §7.8.1)

**Назначение:** одна форма: даты, симптомы, связь со справочником болезни, препараты, несколько визитов врача, анализов с фото, фото рецептов; удаление записи.

**Figma:** форма записи (например 359).

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/me/disease-records/` | JWT — создать |
| **GET** | `/api/me/disease-records/<pk>/` | JWT — полная карточка |
| **PATCH** | `/api/me/disease-records/<pk>/` | JWT — обновить |
| **DELETE** | `/api/me/disease-records/<pk>/` | JWT — удалить |

**Тело POST/PATCH (ядро):**

```json
{
  "date_of_illness": "2026-03-01",
  "title": "ОРВИ",
  "disease_id": 5,
  "subject_user_id": null,
  "symptoms": "текст симптомов",
  "drug_ids": [1, 2],
  "doctor_visits": [
    {
      "visit_date": "2026-03-02",
      "specialty": "Терапевт",
      "doctor_full_name": "…",
      "diagnosis": "…",
      "medicines_text": "…",
      "procedures_text": "…"
    }
  ],
  "analyses": [
    { "taken_date": "2026-03-03", "name": "ОАК", "result_text": "…", "photo": null }
  ],
  "prescriptions": [{ "photo": null, "note": "" }]
}
```

Если переданы массивы `doctor_visits` / `analyses` / `prescriptions`, они **заменяют** прежние списки у этой записи.

### 7.1. Визиты, анализы, рецепты отдельными URL

**Назначение:** добавлять по одному блоку «+», не пересылая всю запись.

| Ресурс | Список/создание | Одна сущность |
|--------|-----------------|---------------|
| Визиты | **GET/POST** `/api/me/disease-records/<record_id>/doctor-visits/` | **GET/PATCH/DELETE** `/api/me/doctor-visits/<pk>/` |
| Анализы | **GET/POST** `/api/me/disease-records/<record_id>/analyses/` | **GET/PATCH/DELETE** `/api/me/analyses/<pk>/` |
| Рецепты | **GET/POST** `/api/me/disease-records/<record_id>/prescriptions/` | **GET/PATCH/DELETE** `/api/me/prescriptions/<pk>/` |

### 7.2. Распознавание текста с фото анализа (ИИ)

**Назначение:** ТЗ §8.2.4 — загрузили фото анализа, получили текст в поле результата.

| Метод | Путь | Query | Auth |
|-------|------|-------|------|
| **POST** | `/api/me/analyses/<pk>/ocr/` | `mode=append` (по умолчанию) или `replace` | JWT |

У анализа должно быть загруженное фото; результат дописывается в `result_text` или заменяется целиком.

### 7.3. Голосовой ввод в поля формы (ТЗ §8.2.2)

**Назначение:** записать аудио, получить текст для вставки в поле.

| Метод | Путь | Формат | Auth |
|-------|------|--------|------|
| **POST** | `/api/me/voice/transcribe/` | **multipart**: `audio`, опционально `field` | JWT |

**Сейчас:** ответ **501** и JSON-заглушка — реальный STT подключается отдельно.

## 9. Справочник лекарств (ТЗ §7.10–7.10.2)

**Назначение:** поиск, карточка с инструкцией и «можно лечить», метка «в аптечке», недавно просмотренные, отзывы, звёзды, обсуждение, аналоги.

**Figma:** поиск и список (428), детальная карточка (361), отзывы.

### 9.1. Поиск и карточка

| Метод | Путь | Query | Auth |
|-------|------|-------|------|
| **GET** | `/api/catalog/drugs/` | `q` | не обязательно |
| **GET** | `/api/catalog/drugs/<pk>/` | — | не обязательно |

В карточке для авторизованного: **`in_my_cabinet`**: `true`, если препарат есть в «Моей аптечке».

### 9.2. Ранее просмотренные (ТЗ этап 2)

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/me/recent-drugs/?limit=30` | JWT |

**Ответ:** `{ "title": "…", "items": [ …как DrugSerializer… ] }`.

### 9.3. Запись факта просмотра карточки

**Назначение:** обновить лог просмотра для блока «Недавние» (не фильтр — **изменение состояния**, поэтому **POST**).

| Метод | Путь | Auth |
|-------|------|------|
| **POST** | `/api/catalog/drugs/<pk>/view/` | JWT |

**Ответ:** `{ "ok": true, "drug_id": <pk> }`.

### 9.4. Отзывы (список + отправка на модерацию)

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/catalog/drugs/<drug_id>/reviews/` | нет — только одобренные |
| **POST** | то же | JWT |

**POST тело:** `{ "rating": 1–5, "text": "…" }`. **Ответ 201:** `{ "ok": true, "status": "pending" }`.

### 9.5. Оценка звёздами (не чаще 1 раза в 24 ч)

| Метод | Путь | Тело | Auth |
|-------|------|------|------|
| **POST** | `/api/catalog/drugs/<drug_id>/star-rating/` | `{ "stars": 1–5 }` | JWT |

**Ответ:** обновлённый объект препарата.

### 9.6. Обсуждение

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/catalog/drugs/<drug_id>/discussion/` | JWT |
| **POST** | то же | JWT |

**POST:** `{ "body": "…" }`.

### 9.7. Аналоги

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/catalog/drugs/<drug_id>/analogs/` | нет |

**Ответ:** `[{ "id", "name", "price" }, …]`.

## 11. Уведомления: события и напоминания (ТЗ §7.12.1)

**Назначение:** лента событий (в т.ч. пользовательские напоминания), отметка прочитанного, создание напоминания с датой/временем и подписью «для кого» (семья). Иконка на главной и обновление списка без опроса — через WebSocket.

**Figma:** вкладка «События», форма «Заметка» (369, 343–344).

### 11.1. REST: список, создание, прочитано

| Метод | Путь | Назначение | Auth |
|-------|------|------------|------|
| **GET** | `/api/me/notifications/events/` | До 200 событий | JWT |
| **POST** | `/api/me/notifications/events/` | Создать напоминание | JWT |
| **POST** | `/api/me/notifications/events/<pk>/read/` | Пометить прочитанным | JWT |

**Элемент списка:** `id`, `kind`, `title`, `body`, `link_url`, `read_at`, `event_at`, `subject_user_label`, `created_at`.

**Тело POST создания:**

```json
{
  "title": "Заметка",
  "body": "Текст",
  "event_at": "2026-05-10T12:40:00Z",
  "subject_user_label": "Имя на бейдже в списке"
}
```

**Ответ 201:** `{ "id": <новый id> }`.

### 11.2. WebSocket: push при изменении событий

**Назначение:** сразу обновить UI (бейдж, список), когда на сервере создали или изменили `NotificationEvent` для этого пользователя (в т.ч. после `…/read/`).

| Параметр | Значение |
|----------|----------|
| URL | `ws://` или `wss://<хост>/ws/notifications/?token=<JWT_access>` |
| Токен | Тот же **access**, что в `Authorization` |

**Первое сообщение после connect:**

```json
{ "op": "hello", "notifications": [ /* до 30 последних */ ] }
```

**Далее при каждом сохранении в БД:**

```json
{ "op": "notification", "created": true|false, "notification": { /* те же поля, что в REST */ } }
```

**Ошибка токена:** закрытие с кодом **4001**.

> **Чат поддержки** по WebSocket **не** реализован — только REST (раздел 14).

## 14. Меню: о компании и конфиденциальность (ТЗ §7.15–7.16)

**Назначение:** статический текст из админки без логики на клиенте.

**Figma:** пункты меню (374), экраны текста (383, 325).

| Метод | Путь | Auth |
|-------|------|------|
| **GET** | `/api/content/pages/<slug>/` | нет |

Примеры `slug`: `about`, `privacy` — как создано в админке `StaticPage`.

## 15. Обратная связь (ТЗ §7.17)

**Назначение:** письмо в поддержку (сохранение в БД + почта при настройке), чат с оператором через REST.

**Figma:** выбор «Чат» / «Письмо» (372), форма письма (375), переписка (382–381).

### 15.1. Письмо

| Метод | Путь | Тело | Auth |
|-------|------|------|------|
| **POST** | `/api/support/feedback/` | `{ "message", "subject?", "email?" }` | JWT |

### 15.2. Чат (опрос новых сообщений)

| Действие | Метод | Путь |
|----------|-------|------|
| Список тредов | **GET** | `/api/me/chat/threads/` |
| Создать тред | **POST** | `/api/me/chat/threads/` — тело `{ "title": "Поддержка" }` |
| Сообщения | **GET** | `/api/me/chat/threads/<thread_id>/messages/` |
| Отправить | **POST** | то же — тело `{ "body": "…" }` |

Элемент сообщения: `id`, `body`, `is_staff`, `created_at`, `sender_id`. **WebSocket для чата нет** — обновление списка по таймеру или после отправки.

## 20. Что в ТЗ есть, но в этом API ещё не закрыто полностью

| Тема | Пояснение |
|------|-----------|
| Регистрация по SMS-коду | В ТЗ §7.3 — по телефону; в API — **email/username + пароль** и соцсети |
| Пуши FCM по расписанию напоминаний (за 24 ч, 3 ч …) | Событие с `event_at` сохраняется; **серверные cron-пуши** в репозитории не описаны |
| Чат в реальном времени | Только **REST**; **WS** только для **уведомлений** (раздел 11) |
| Запись к врачу §7.19 | Отдельного модуля нет |
| AppMetrica, парсеры цен, свой NN на сервере | Вне текущего контракта; см. `docs/STAGE2.md` |
