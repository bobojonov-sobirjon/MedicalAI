# MedicalAI — qilingan ishlar (2026-05-30)

Ushbu hujjat so‘nggi sessiyada amalga oshirilgan o‘zgarishlarni jamlaydi: Relax admin xatosi, apetchka foto orqali tanish, RuTronix xatolari bilan ishlash.

---

## 1. Relax admin — JSON 500 xatosi

### Muammo
`/admin/medic/relaxasset/<id>/change/` sahifasida saqlash (POST) vaqtida foydalanuvchi HTML o‘rniga JSON ko‘rardi:

```json
{"detail": "Внутренняя ошибка сервера."}
```

**Asl sabab (server log):** `PermissionError` — Gunicorn `www-data` foydalanuvchisi `/var/www/MedicalAI/media` papkasiga yozolmayapti (fayl yuklashda).

**Qo‘shimcha sabab:** `JsonErrorResponseMiddleware` barcha admin xatolarini JSON qilib yuborardi — haqiqiy traceback yashirin qolardi.

### Qilingan o‘zgarish
**Fayl:** `config/middleware/middleware.py`

- `/admin/` yo‘llarida middleware endi xatoni JSON ga aylantirmaydi — Django admin odatdagi HTML xato sahifasini ko‘rsatadi.
- `Custom404Middleware` ham admin uchun JSON 404 qaytarmaydi.

### Serverda qo‘lda tuzatish (deploy)
```bash
mkdir -p /var/www/MedicalAI/media/relax
chown -R www-data:www-data /var/www/MedicalAI/media
chmod -R 755 /var/www/MedicalAI/media
systemctl restart medical
```

Yoki `.env` da alohida media:
```
MEDIA_ROOT=/var/www/media
```

## 2. Apetchka — foto orqali dori tanish (mijoz talabi)

### Maqsad
Foydalanuvchi dori qutisining suratini yuboradi → AI nomni o‘qiydi → apetchkaga qo‘shiladi. Qo‘lda har bir dori nomini yozish shart emas.

**Mijoz qo‘shimcha talabi:** stolga bir nechta dori qo‘yib bitta surat — hammasini tanish.

### API endpoint
```
POST /api/me/cabinet/recognize/
Authorization: Bearer <JWT>
Content-Type: multipart/form-data
```

| Parametr | Joyi | Qiymat | Tavsif |
|----------|------|--------|--------|
| `image` | body (file) | **majburiy** | Dori qutisi yoki bir nechta quti surati |
| `mode` | query yoki body | `single` (default) | Bitta quti |
| `mode` | query yoki body | `batch` | Bir suratda ko‘p dori |
| `add_to_cabinet` | query yoki body | `true` / `false` | Tanilgandan keyin darhol apetchkaga qo‘shish |

### Rejimlar

#### `mode=single` — bitta dori
**Misol javob (muvaffaqiyat):**
```json
{
  "mode": "single",
  "recognized_name": "Эликвис",
  "matched_drug_id": 146,
  "matched_drug": { "id": 146, "name": "Эликвис", ... },
  "added_to_cabinet": true,
  "already_in_cabinet": false,
  "cabinet_item": { "id": 14, "display_name": "Эликвис", ... }
}
```

#### `mode=batch` — stol surati
```json
{
  "mode": "batch",
  "count": 3,
  "items": [
    {
      "recognized_name": "Эликвис",
      "matched_drug_id": 146,
      "matched_drug": { ... },
      "added_to_cabinet": true,
      "already_in_cabinet": false,
      "cabinet_item": { ... }
    }
  ]
}
```

### Biznes-logika
1. Surat **RuTronix** (asosiy) yoki **Gemini** (zaxira) ga yuboriladi.
2. AI **brend nomi** ni oladi (masalan «Эликвис», «апиксабан» emas).
3. Nom `Drug` jadvalida qidiriladi; topilmasa **yangi kartochka yaratiladi** (TZ §7.14).
4. `add_to_cabinet=true` bo‘lsa — `CabinetItem` yaratiladi.
5. Apetchkada allaqachon bo‘lsa — dublikat qo‘shilmaydi (`already_in_cabinet: true`).

### O‘zgartirilgan fayllar

| Fayl | O‘zgarish |
|------|-----------|
| `apps/core/gemini.py` | `_complete_drug_vision_plain`, `recognize_drug_names_from_image` (batch), yaxshilangan prompt |
| `apps/cabinet/services.py` | `resolve_drug_from_name`, `recognize_cabinet_batch`, `add_recognized_to_cabinet`, `build_recognition_result` |
| `apps/cabinet/views.py` | `CabinetRecognizeView` — `mode`, `add_to_cabinet`, xato qayta ishlash |
| `scripts/smoke_test_api.py` | `mode=batch` smoke test qo‘shildi |

### Swagger
`/docs/` → tag **«Аптечка»** → **«Распознать лекарство(а) по фото»**

## 3. RuTronix xatolari va Gemini zaxira

### Muammo
RuTronix `500 Internal Server Error` qaytarganda backend ham 500 berardi (`httpx.HTTPStatusError` ushlanmagan edi).

### Qilingan o‘zgarish

**Fayl:** `apps/core/rutronix.py`
- Yangi exception: `RuTronixUpstreamError` (5xx javoblar uchun).
- 401 → `RuTronixUnauthorized`, 402 → `RuTronixPaymentRequired`.

**Fayl:** `apps/core/gemini.py`
- RuTronix 500 yoki balans tugasa → avtomatik **Gemini** ga o‘tish (agar `GEMINI_API_KEY` bor bo‘lsa).

**Fayl:** `apps/cabinet/views.py`
- 503 — kalit/balans muammosi (tushunarli xabar).
- 502 — RuTronix vaqtincha ishlamayapti.
- 504 — timeout.

### `.env` talablari
```env
RUTRONIX_API_KEY=...          # asosiy (tavsiya)
GEMINI_API_KEY=...            # zaxira (RuTronix ishlamasa)
```

## 4. Mobil ilova uchun integratsiya qisqacha

### Oqim A — bir bosishda qo‘shish
```
Foto → POST /api/me/cabinet/recognize/?add_to_cabinet=true
     → Ekranda: «Эликвис qo‘shildi»
```

### Oqim B — avval ko‘rsat, keyin tasdiqlash
```
Foto → POST /api/me/cabinet/recognize/ (add_to_cabinet=false)
     → «Эликвис — to‘g‘rimi?» → [Ha] → POST /api/me/cabinet/items/ { "drug": 146 }
```

### Oqim C — stol surati (batch)
```
Foto → POST /api/me/cabinet/recognize/?mode=batch&add_to_cabinet=true
     → Ro‘yxat ko‘rsatish (items[])
```

### UI tavsiyasi
- **«Добавить фото»** o‘rniga yoki yonida: **«Распознать по фото»**
- Yuklash vaqtida loading indicator (OCR 10–30 s davom etishi mumkin)
